# Requirement Priorities

## 1. Priority Model

The project uses:

- **Must Have:** essential to demonstrate the approved objectives.
- **Should Have:** important but can follow the core implementation.
- **Could Have:** optional enhancements implemented only if time/resources permit.

## 2. Must Have

- Temperature monitoring.
- Humidity monitoring.
- IoT data transmission.
- Environmental data storage.
- Real-time dashboard.
- Produce batch registration.
- QR-code generation.
- QR-code traceability.
- Produce movement recording.
- Blockchain record implementation.
- Blockchain integrity verification.
- Basic authentication/authorization.

## 3. Should Have

- Environmental alerts.
- Historical graphs.
- Device status monitoring.
- Search/filtering.
- System logging.
- Data export.
- Additional usability refinements.

## 4. Could Have

- Advanced analytics.
- Additional environmental sensors.
- Advanced notifications.
- Extended reporting.
- Other enhancements not required to demonstrate the four objectives.

## 5. Scope Rule

If time becomes constrained, Could Have features shall be deferred before reducing testing or evidence for Must Have requirements.
